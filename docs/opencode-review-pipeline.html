OpenCode PR Review — Pipeline Flow

opencode-review GitHub Action · v4.3.4
What it does: turns a /review comment on a pull request into an AI code review that posts inline comments and a PASS/FAIL verdict. Read left→right, top→bottom.
Trigger PR comment /review (or manual dispatch)
Feeds in PR diff · repo REVIEW.md · org context profiles · Serena symbols (optional)
You get back Inline comments · verdict comment · cost/telemetry

Guard rails

Never reviews the same commit twice; re-reviews are restricted to the PR author or trusted members.

Fails gracefully

If Serena or the repo's REVIEW.md is missing/invalid, it degrades to org-default rules instead of aborting.

Transparent cost

Every run reports token usage, dollar cost, and timing so reviews stay measurable.

Repository Map — every folder & file, and its job
PathWhat it is / does
Entry point & orchestration
action.ymlThe composite GitHub Action. Declares inputs (model, API key, org_profiles, markers, Serena SHA…) and the ordered steps that run the whole pipeline (Lanes A–C). This is the only file a consuming repo references.
src/ — TypeScript source (authoring)
src/context/resolve-manifest.tsLoads the repo's REVIEW.md, validates it, merges with org defaults, and classifies status as READY / READY_WITH_GAPS / BLOCKED.
src/context/lib/review-manifest.tsShared library: parse / validate / merge manifest logic + the org-profile allow-list. Imported by resolve-manifest and compile-ocr-rules.
src/context/fetch-serena-context.tsQueries the Serena MCP server for symbol definitions of changed files; writes serena-context.md.
src/ocr/compile-ocr-rules.tsMerges org context profiles + repo directives into the single ocr-rule.json the engine consumes. Includes path-safety guards (no symlinks, no traversal).
src/ocr/remap-anchors.tsDrops outdated review anchors and keeps current line numbers so old comments map to the right lines.
src/ocr/resolved-directives.tsTurns resolved review threads into "don't re-flag this" directives for the engine.
src/ocr/build-background.tsAssembles the LLM background file (prior human discussion + Serena context) within a byte budget.
src/ocr/post-findings.tsCore result logic: maps findings to diff lines, de-dupes against existing threads, builds inline comments + the PASS/FAIL verdict comment.
src/ocr/compute-cost.tsConverts token counts into a dollar cost using the optional ocr_cost_rates table.
src/ocr/append-measurement.tsBuilds the per-run measurement row (verdict, severity tally, tokens, cost, tool calls).
src/**/*.test.tsUnit tests colocated next to each module — every logic file has a matching .test.ts.
dist/ — compiled JavaScript (what actually runs)
dist/context/*.js
dist/ocr/*.js		Transpiled output of src/. action.yml invokes these with node dist/.... .js.map = source maps; .test.js = compiled tests. Edit src/, never dist/.
context/ — the reviewing knowledge base
context/contexts/backend/security.md
context/contexts/backend/sre.md
context/contexts/frontend/security.md
context/contexts/frontend/sre.md		Organization review profiles selected via the org_profiles input. Each declares mandatory_rule_ids (e.g. ORG-SEC-001) the reviewer must always enforce.
context/defaults/REVIEW.mdFallback manifest used when a repo has no valid REVIEW.md of its own (drives the "ran with ORG-DEFAULT rules" warning).
context/defaults/REVIEW.example.mdCopy-paste template showing repos how to author their own REVIEW.md.
context/defaults/manifest-defaults.jsonBaseline limits: excluded paths, diff-size caps (100 files / 5000 lines), docs-only paths, default review directives.
